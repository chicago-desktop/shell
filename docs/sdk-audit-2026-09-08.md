# Bringing windows onto the SDK — 8 September 2026

Contract: [Window SDK](sdk.md). Checked: the `tui_desktop.window` entries in the
Windows module and the compositor mechanics of `butschster/tui-desktop`. This is an audit of the client
SDK, not a repeat of the security audit of the whole test stand.

## What diverged and what was changed

- Registration: ordinary windows were already discovered through the registry, but every new
  pixel view required editing the theme. Added one shared renderer and the
  declarative loop `sdk:app`; the executable example is connected by an entry alone.
  `group` now supports both a string path and an array of segments.
- Geometry: there was no single type for the client rectangle. Added
  `geometry` and a shared `ui.plan` for presentation and hits. Custom views
  keep their domain layouts with an explicit translation into SDK units.
- Mouse: the compositor swallowed motion and release. Added client capture;
  the thumb of the declarative list can be dragged beyond the window's bounds.
- Closing: pixel providers were terminated immediately. Both transports now
  receive `close` and a shared deadline for shutting down. The theme gets `forget(id)` to
  release the separate cache of the picture viewer.
- Metadata: opening a cell window directly lost the title from the entry,
  and an application without an argument received the Bash command. Title and arguments
  are brought into line with the pixel path; the command stays with the PTY.
- Scrolling: a shared `scroll` appeared, with bounds, visibility of the selected row,
  the wheel and scrollbar geometry. The explorer, the Task Manager lists, the registry tree,
  Notepad and picture panning use it to clamp the offset.

## Existing applications

- **My Computer** — its own icon grid, two backends. Kept the unit
  "row of icons" and one row per wheel step. Fixed Page Down, End and the action
  repeating on key release; the bounds are computed by the shared `scroll`.
- **Task Manager** — its own tables, tabs and graphs, two backends.
  Normalization/reveal of the selected row use the shared `scroll`. The non-overlapping
  slicing of the pixel page is kept; the first-tick regression stays in the tests.
- **Run** — its own command editor and asynchronous open replies,
  two backends. Uses the shared window API and event normalization. Launching goes
  through the compositor; the SDK does not duplicate the Bash domain model.
- **Notepad** — a text viewer in cells. When shrunk it no longer substitutes
  a fake 60×18; vertical and horizontal scrolling are clamped to the content.
  It is a viewer without saving and without the promise of a full text editor.
- **Calculator** — its own fixed buttons and pixel styling.
  Moved to the shared channel/state publishing; right click and key release do not
  perform the calculation, closing is handled normally.
- **Date/Time** — its own clock/calendar, pixel styling.
  Shared channel/state and correct shutdown; only a left click activates the buttons.
- **Registry viewer** — its own tree and value pane. Shared event
  normalization and bounds with an explicit `first - 1` adapter. Real small geometry is no longer
  replaced with the minimum one; in it the renderer explains the required size.
  A registry read error is kept rather than overwritten by a healthy empty snapshot.
- **Picture viewer** — its own pixel view. The offset is clamped in the
  provider after zoom/resize, so returning from the edge has no "dead"
  zone. The size is obtained by decoding the bytes under the provider's permissions.
  The cache distinguishes images of the same size and releases the frame of a closed window.
- **Bash/PTY** — terminal content. Its scrolling and resizing are determined by the PTY;
  the shell only passes the size and events; a terminal
  program must not be wrapped in an additional SDK list.

## Windows of the test stand itself and of the workshop

In `kickside/src/app/desktop` a hidden `app.desktop:window_calc` remains: it is a
text calculator example. It does not duplicate a menu item; it is given a
fixed size, the shared input normalizer and activation by the left button only.
`gfx_demo` and `win95_demo` are standalone full-screen commands, not window
entries. Their type errors are not part of the window client contract.

In the test stand's `butschster_tui_desktop_windows`, at the time of the check, six
user programs are stored: `commander`, `dataflows`, `dataflow_detail`,
`bridge_runs`, `bridge_jobs`, `clock`. The workshop restores them as
cell windows. Their Lua is stored in the database, not in the module sources; the workshop
so far stores source/modules and the `desktop` import, but not a declarative tree.
`commander` holds cursor/offset and row visibility on its own; the rest
use their own size and display loops. They remain low-level user
clients, not a reference for a new application.

A new declarative window uses a `process.lua` entry from the SDK,
not the old format of a saved workshop program. Existing Lua programs
are not automatically converted into a component tree. Changing their
saved source and extending the workshop format is a separate migration
of user data, which this SDK change does not pretend to be.

## The limit of unification

Existing specialized views are not renamed as declarative: their
tables, tree, menu and graphs are not SDK components yet. They must
follow the same contract for transport, geometry and scroll bounds.
New standard forms use `sdk:app`; the component set is extended
in one shared layer with two backends.

A fixed `split` is not a draggable divider. The scrollbars of the explorer, the registry and the pixel Task Manager keep their styling,
but use the shared `scroll.bar` and `scroll.pointer` for geometry and dragging.
The text Task Manager keeps keyboard and wheel control of the list. The pixel clock,
calculator, tree and pictures did not get functional text counterparts:
a text caption of the state does not equal support of the whole interface.

## Verifiable evidence

`test/src/sdk_test.lua` checks real discovery, dual-mode launch,
client resize, mouse capture, closing, layout bounds, empty data,
Page Down, UTF-8 and raster reuse. The example produces
`test/shots/sdk-controls.png`. The shared Windows and compositor suites additionally
check the earlier applications and ownership of child windows.

# Ревью SDK окон и унификация компонентов — 8 сентября 2026

Что проверялось: `src/sdk/*` против `docs/sdk.md` и тестов; каждое готовое
окно против SDK и библиотек основы (`geometry`, `scroll`, `input`,
`window_api`); все кнопки приложения против эталона Windows 95. Отдельно —
что [аудит миграции](sdk-audit-2026-09-08.md) назвал сделанным и что из этого
не подтверждается кодом. Здесь ответ на один вопрос: **что должно стать одним
компонентом, а сейчас существует в нескольких видах.**

Что исправлено в этом ревью сразу, отмечено «✔ исправлено»; остальное —
план, по пунктам, в порядке выполнения.

## 1. Вердикт по SDK

Механика правильная и единственная в проекте, где кнопка ведёт себя как в
Windows: взводится нажатием, срабатывает по отпусканию внутри, отменяется
уводом мыши; отпускание клавиши и правая кнопка игнорируются; Tab ходит по
фокусу. Дерево — простые таблицы, план один для рисования и попаданий. Это
основа, которую стоит держать; окна, написанные «по образцу диспетчера»,
хуже её по всем этим пунктам.

## 2. Аудит миграции против кода

Аудит честно называет специализированные окна специализированными; но
несколько утверждений «использует общий …» кодом не подтверждаются:

- «Диспетчер задач … нормализация/показ выбранной строки используют общий
  `scroll`» — верно, но **нормализации ввода в ячейках нет** (`taskman/window.lua:341`),
  `pgdn`/`page_down` не приводятся; кнопка «Обновить» есть и нажимается **только в
  пиксельном режиме**; вкладок три реализации (`widgets.tabs`, `taskman/render`,
  `datetime/render`); ветка `"track"` в `taskman/layout.lua:448` не соединена со
  `scroll.drag` — мёртвый путь.
- «Выполнить … использует общий API окна и нормализацию» — верно, но **редактор
  строки у него свой целиком** (`run/model.lua:5-63`) при наличии `sdk/editor.lua`,
  и **один диалог рисует `default` по двум правилам**: в пикселях всегда «ОК»
  (`run/render.lua:67`), в ячейках — та кнопка, что в фокусе (`run/window.lua:52`).
  Enter при этом делает одно, а показано разное.
- «Дата и время … только левый клик активирует кнопки» — верно, но `state.pressed`
  **никогда не публикуется** (`render.lua:290` мёртв), у «ОК» нет `default`, хотя
  Enter её жмёт; кнопки ▾ и счётчика — бутафория без попаданий.
- «Просмотр реестра … общие нормализация событий и границы» — верно, но рядом
  остались свои `PAGE_UP/PAGE_DOWN` и свой `reveal` (`controller.lua:67-74,168-169`).
- «Мой компьютер … границы считает общий `scroll`» — верно; но панель
  инструментов, адресная строка и меню в пикселях нарисованы **заново** своим
  кодом (`render_pixels.lua:74-160`), а не тем, чем в ячейках; акселератор меню
  подчёркнут в ячейках и не подчёркнут в пикселях, и не работает нигде.

## 3. Кнопки: десять рисовалок одной детали

| Где | Чем | Чего не хватает до эталона |
|---|---|---|
| `widgets.button` (ячейки) | своя | ✔ теперь `disabled`, `focused`; акселератор был |
| `pixels.button` (пиксели) | **эталон**: default, pressed со сдвигом, этчед, пунктир фокуса | акселератора нет; подпись центрируется по исходному прямоугольнику, а не по сжатому `default` |
| SDK ячейки | была «[ … ]» | ✔ теперь `widgets.button` |
| SDK пиксели | `pixels.button` | акселератор |
| заголовок окна, ячейки `chrome.lua:386` | своё `bezel` | нет нажатия |
| заголовок окна, пиксели `chrome_pixels.lua:391` | `pixels.panel` — одинарная грань | не `pixels.button`, никогда не нажимается, своя геометрия (16 px против шага в 3 ячейки) |
| «Пуск», пиксели `chrome_pixels.lua:463` | `pixels.panel` + `bevel` | не `pixels.button` |
| панель проводника, пиксели `render_pixels.lua:102` | `pixels.panel/bevel` | не `pixels.button`; одинарная грань |
| ▾ адресной строки (оба) | `bezel`/`panel` | не бывает нажатой |
| стенд: `window_calc.lua`, `gfx_demo.lua`, `win95_demo.lua` | три своих | плоские плитки / локальные копии `bevel` |

Несогласованности поведения:

- **Момент активации.** По отпусканию внутри — только SDK. По нажатию — calc,
  datetime, run, taskman, explorer, regedit, композитор. Правило: активация по
  отпусканию внутри, как в Windows; для клавиатуры — Enter и пробел на фокусе.
- **Правая кнопка.** Игнорируется везде, кроме композитора основы
  (`library.lua:1271`): правый щелчок по заголовку закрывает окно, по «Пуску»
  открывает меню. Чинится одной проверкой `event.button == "left"`.
- **`default`.** Есть у Run и в SDK; нет там, где Enter реально работает —
  datetime «ОК», ✔ appwiz («Закрыть», «Да», «Записать» теперь помечены).
- **`disabled`.** Этчед только в `pixels.button`; `widgets.toolbar` и пиксельная
  панель проводника — просто серый; проводник на щелчок по недоступной кнопке
  отвечает сообщением вместо тишины.
- **Акселераторы.** `widgets.accel` не используется ни одной кнопкой продукта;
  `pixels.button` подчёркивать не умеет — в пикселях акселераторов нет физически.
- **Фокус.** Понятие есть только в SDK и Run. Tab-обход — только там же.

## 5. План унификации, по порядку — и что из него сделано 2026-09-08

Сделано в тот же день (все наборы зелёные: основа 58, оболочка 191):
кнопка одна на бэкенд (`widgets.button` со всеми состояниями, `pixels.button`
с акселератором; «Пуск», панель и ▾ проводника, «Обновить» диспетчера,
«ОК» даты, оба режима Run — на ней; композитор реагирует только на левую);
компоненты `statusbar`, `tabs`, `menu`, `table` (и без заголовка), `tree`,
`group`, `graph`, `gauge`, `field`, `image`, `label.alert`; цикл `app.run`
переписан (см. A6–A13); **Run, калькулятор, диспетчер задач и реестр
переехали на SDK целиком**, их собственные раскладки, контроллеры и
отрисовщики удалены, `chrome_pixels.VIEWS` сжался до проводника, картинок и
«Даты и времени»; `whole()` заменён на `geometry.whole` в 18 файлах, семь
разборов UTF-8 сведены к `desktop:text.runes`, график и потолок — в
`sdk:charts`. Попутно найдена ловушка VM: после ошибки под `pcall` замыкание
и владелец перестают делить локальную переменную (CLAUDE.md стенда).

Осталось: «Дата и время» (вкладки, календарь, стрелочные часы — собственный
вид; кнопки уже общие), проводник, Блокнот и картинки — собственные
отрисовщики; у них ещё свои полосы прокрутки и статусные строки в пикселях;
активация по отпусканию есть только в SDK-окнах; `interaction` не
освобождает записи исчезнувших контролов (A11); `selected` по ID (A12).

1. **Кнопка — одна в ячейках, одна в пикселях, обе со всем набором состояний.**
   `widgets.button` (✔ default/pressed/disabled/focused/accel) и `pixels.button`
   (добавить акселератор, центрировать по сжатому прямоугольнику). Перевести на
   них: заголовок окна и «Пуск» в обоих хромах (с одной геометрией кнопок
   заголовка), панель и ▾ проводника в пикселях, «Обновить» диспетчера в обоих
   режимах, кнопки datetime (и опубликовать `pressed`), калькулятор (уже
   `pixels.button`). Композитору — проверку левой кнопки. Активация везде по
   отпусканию внутри — через `ui`-подобный `armed`, вынесенный в `input`.
2. **Компоненты, которых не хватает четырём окнам сразу:** `statusbar`, `tabs`,
   `menu` (строка меню окна; таблицы пунктов уже объявлены у проводника,
   реестра, калькулятора). Каждый — одна раскладка, два отрисовщика, тест
   поведения, абзац в `docs/sdk.md`.
3. **Цикл `app.run`:** дополнительные каналы (`definition.channels` или
   `context.watch(ch)`), `pcall` вокруг `view/update` с уборкой, штатный отказ
   композитора без `assert`, `close` и сырые клавиши как действия в `update`.
   Без этого Run и диспетчер на SDK не переезжают.
4. **Перенос окон:** Run (после 3 — весь интерфейс это `label + input + 2 button`),
   калькулятор (нужны `menu` и цвет подписи кнопки), диспетчер вкладки
   «Приложения»/«Процессы» на `table` (нужны `tabs`, графики остаются свои),
   правая панель реестра на `table` + `split`. Проводник, Блокнот, картинки
   остаются собственными отрисовщиками, но обязаны отдать дубли из §4.
5. **Дубли из §4** — механически, файл за файлом; проверяется тем, что копия
   удалена, а не тем, что «работает и так».

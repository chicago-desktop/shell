## 1. Вердикт по SDK

Механика правильная и единственная в проекте, где кнопка ведёт себя как в
Windows: взводится нажатием, срабатывает по отпусканию внутри, отменяется
уводом мыши; отпускание клавиши и правая кнопка игнорируются; Tab ходит по
фокусу. Дерево — простые таблицы, план один для рисования и попаданий. Это
основа, которую стоит держать; окна, написанные «по образцу диспетчера»,
хуже её по всем этим пунктам.

Что в SDK не выдерживает своего же контракта:

- **A1** — Дефект: `list_event` брал сдвиг из плана, а не из состояния: два колеса подряд без перерисовки теряли первое; Где: `ui.lua`; Состояние: ✔ исправлено
- **A2** — Дефект: Метка с `id` брала фокус по щелчку, а в `focusable` её нет — Tab молча умирал до перезапуска окна; Где: `ui.lua`; Состояние: ✔ исправлено; 2026-09-11 — и для остальных пассивных видов с `id` (`field`, `group`, `statusbar`, `image`, `graph`, `gauge`…): щелчок проверяет `passive`, а не имя `label`
- **A3** — Дефект: Щелчок по колонке полосы, когда прокручивать нечего, выбирал строку; Где: `ui.lua`; Состояние: ✔ исправлено
- **A4** — Дефект: Колесо во время взвода кнопки или перетаскивания ползунка крутило список; Где: `ui.lua`; Состояние: ✔ исправлено
- **A5** — Дефект: Кнопка в ячейках рисовалась своей «[ … ]»: без граней, без чёрного контура `default`, без нажатия — не Windows и не то, что рисуют Run и проводник; Где: `cells.lua`; Состояние: ✔ исправлено: `widgets.button` с `default/pressed/disabled/focused`
- **A6** — Дефект: Ошибка во `view`/`update` (например, два одинаковых `id`) рвёт окно мимо `dispose`, `desktop.close`, `tty.stop`; в ячейках терминал остаётся со спрятанным курсором; Где: `app.lua:58-62`; Состояние: ✔ исправлено: `pcall` вокруг `init/view/update/plan`, запасное дерево с «Закрыть»; 2026-09-11 — под той же охраной кадр ячейками (`cells.rows`/`surface:present`), разбор события и `ui.event`
- **A7** — Дефект: `assert(desktop.publish_state(...))` и `assert(desktop.close(...))` превращают штатный отказ композитора в смерть окна; Где: `app.lua:32,62`; Состояние: ✔ исправлено: отказ композитора не смерть окна
- **A8** — Дефект: Общий отрисовщик проверяет только `state.sdk == 1`; состояние без `interaction` роняет кадр всей оболочки (`chrome_pixels` зовёт `placement` без `pcall`); Где: `render.lua:12-13`; Состояние: ✔ 2026-09-11: `render.placement` проверяет форму (`ui` — дерево, `interaction` подставляется пустым) и само дерево `ui.problem` — плохое дерево даёт текст в окне, а не ошибку. `pcall` вокруг вида в `chrome_pixels` НЕ поставлен нарочно: пойманная ошибка в go-lua рвёт upvalue и у кадров ниже, то есть у цикла композитора (растяжка в `sdk_test`)
- **A9** — Дефект: Отрисовщик мутирует `interaction` (offsets, focus) в копии состояния у композитора; план строится до `store.take` и выбрасывается при `dirty == false`; Где: `render.lua:13`; Состояние: план
- **A10** — Дефект: Цикл `app.run` закрыт: только события и один таймер. Нет канала под `desktop.replies()` (нужен Run и проводнику) и под свои данные; `update` синхронный. Это главное, что мешает переносу Run и диспетчера; Где: `app.lua:40-45`; Состояние: ✔ исправлено: `context.watch/unwatch`, `close` и `key` действиями, `update` может вернуть `false`
- **A11** — Дефект: `interaction.offsets/editors` не освобождаются при смене дерева; `capture`/`armed` не снимаются, если композитор снял захват без `release` (сворачивание); Где: `ui.lua`; Состояние: ✔ исправлено: `ui.plan` освобождает записи исчезнувших контролов, снимает захват и взвод
- **A12** — Дефект: `selected` принимает только номер строки, хотя документ советует хранить выбор по ID; `selected == nil` + «вниз» даёт вторую строку; Где: `ui.lua`, оба отрисовщика; Состояние: ✔ исправлено: `selected` принимает ID предмета; 2026-09-11 — без выбора стрелка выбирает первую строку (список, таблица, дерево, значки)
- **A13** — Дефект: Приложению не доходят «сырые» клавиши: Esc, F5 не обработать; `close` не попадает в `update`; Где: `ui.event`, `app.lua`; Состояние: ✔ исправлено
- **A14** — Дефект: Пробел на кнопке работает только при `key_type == "runes"`; Shift+Tab зависит от терминала (`backtab` не нормализуется); Где: `ui.lua`, `input.lua`; Состояние: план

Расхождения двух отрисовщиков одного компонента (то, чего контракт «один план
на оба бэкенда» не гарантирует сам по себе):

- **`default` у кнопки** — Ячейки: не было; Пиксели: чёрный контур; Решение: ✔ теперь `widgets.button{default}`
- **нажатие (`armed`)** — Ячейки: не было; Пиксели: вдавлена; Решение: ✔ теперь `widgets.button{pressed}`
- **фокус** — Ячейки: инверсия всей кнопки; Пиксели: пунктир; Решение: ✔ инверсия только подписи; пунктир в ячейках нарисовать нечем
- **отступ строки списка** — Ячейки: 0; Пиксели: 3 px; Решение: план: 1 ячейка и `cell.w` px — одна константа
- **правый край в таблице** — Ячейки: 1 ячейка; Пиксели: 4 px; Решение: план: то же правило
- **обрезка текста** — Ячейки: срез; Пиксели: многоточие; Решение: план: многоточие в обоих (`widgets.clip` умеет)
- **высота поля/кнопки** — Ячейки: на весь прямоугольник; Пиксели: ≤ 23 px по центру; Решение: план: одна высота в ячейках `cell.h`
- **полоса прокрутки** — Ячейки: дорожка `░`; Пиксели: только грани; список и таблица рисуют ползунок разной ширины; Решение: ячейки ✔ 2026-09-11 — список, таблица, дерево и значки рисуют её одним `widgets.scrollbar`; пиксели — план: одна функция полосы в `pixels`
- **`disabled` у списка/таблицы/дерева/значков** — Ячейки: ✔ `face_dim`, без выделения; Пиксели: ✔ лицо и серый текст, без выделения; Решение: ✔ 2026-09-11, как у недоступного поля ввода

## 2. Аудит миграции против кода

Аудит честно называет специализированные окна специализированными; но
несколько утверждений «использует общий …» кодом не подтверждаются:

- «Диспетчер задач … нормализация/показ выбранной строки используют общий
  `scroll`» — верно, но **нормализации ввода в ячейках нет** (`taskman/window.lua:341`),
  `pgdn`/`page_down` не приводятся; кнопка «Обновить» есть и нажимается **только в
  пиксельном режиме**; вкладок три реализации (`widgets.tabs`, `taskman/render`,
  `datetime/render`); ветка `"track"` в `taskman/layout.lua:448` не соединена со
  `scroll.drag` — мёртвый путь.
- «Выполнить … использует общий API окна и нормализацию» — верно, но **редактор
  строки у него свой целиком** (`run/model.lua:5-63`) при наличии `sdk/editor.lua`,
  и **один диалог рисует `default` по двум правилам**: в пикселях всегда «ОК»
  (`run/render.lua:67`), в ячейках — та кнопка, что в фокусе (`run/window.lua:52`).
  Enter при этом делает одно, а показано разное.
- «Дата и время … только левый клик активирует кнопки» — верно, но `state.pressed`
  **никогда не публикуется** (`render.lua:290` мёртв), у «ОК» нет `default`, хотя
  Enter её жмёт; кнопки ▾ и счётчика — бутафория без попаданий.
- «Просмотр реестра … общие нормализация событий и границы» — верно, но рядом
  остались свои `PAGE_UP/PAGE_DOWN` и свой `reveal` (`controller.lua:67-74,168-169`).
- «Мой компьютер … границы считает общий `scroll`» — верно; но панель
  инструментов, адресная строка и меню в пикселях нарисованы **заново** своим
  кодом (`render_pixels.lua:74-160`), а не тем, чем в ячейках; акселератор меню
  подчёркнут в ячейках и не подчёркнут в пикселях, и не работает нигде.

Несогласованности поведения:

- **Момент активации.** По отпусканию внутри — только SDK. По нажатию — calc,
  datetime, run, taskman, explorer, regedit, композитор. Правило: активация по
  отпусканию внутри, как в Windows; для клавиатуры — Enter и пробел на фокусе.
- **Правая кнопка.** Игнорируется везде, кроме композитора основы
  (`library.lua:1271`): правый щелчок по заголовку закрывает окно, по «Пуску»
  открывает меню. Чинится одной проверкой `event.button == "left"`.
- **`default`.** Есть у Run и в SDK; нет там, где Enter реально работает —
  datetime «ОК», ✔ appwiz («Закрыть», «Да», «Записать» теперь помечены).
- **`disabled`.** Этчед только в `pixels.button`; `widgets.toolbar` и пиксельная
  панель проводника — просто серый; проводник на щелчок по недоступной кнопке
  отвечает сообщением вместо тишины.
- **Акселераторы.** `widgets.accel` не используется ни одной кнопкой продукта;
  `pixels.button` подчёркивать не умеет — в пикселях акселераторов нет физически.
- **Фокус.** Понятие есть только в SDK и Run. Tab-обход — только там же.

`selected` по ID, освобождение `interaction`, одна полоса прокрутки и одна

недоступная молчит. Осталось: проводник, Блокнот и картинки — собственные
отрисовщики (по решению: сетка значков, текст с горизонтальной прокруткой и
картинка — не компоненты форм).

1. **Кнопка — одна в ячейках, одна в пикселях, обе со всем набором состояний.**
   `widgets.button` (✔ default/pressed/disabled/focused/accel) и `pixels.button`
   (добавить акселератор, центрировать по сжатому прямоугольнику). Перевести на
